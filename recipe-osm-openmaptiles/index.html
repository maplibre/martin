Building OpenMapTiles from OpenStreetMap

This recipe builds a basemap from an OpenStreetMap extract with the 16 layers of the OpenMapTiles schema. Styles made for OpenMapTiles, such as OSM Bright and Positron can then draw this data.

The configuration is a port of Planetiler's OpenMapTiles profile. It keeps Planetiler's zooms, minimum sizes, buffers, label grids, merges and draw orders. It reads only OpenStreetMap and the ocean polygons of the whole world. It leaves out what Planetiler takes from Natural Earth and Wikidata, see How it differs.

The configuration uses an osm section, described in OpenStreetMap PBF Sources, a shapefile section, described in Shapefile Sources, and the layer keys of Table Source Layers.

Build the tileset

  1. Download an extract, for example Berlin from Geofabrik, and the ocean polygons of the whole world from osmdata.openstreetmap.de, about 900 MB:

    curl -LO https://download.geofabrik.de/europe/germany/berlin-latest.osm.pbf
curl -LO https://osmdata.openstreetmap.de/download/water-polygons-split-3857.zip

  2. Save this as openmaptiles.yaml, next to both downloads:

    openmaptiles.yaml

      layers:

            class: { value: ocean }

Changing the configuration

The configuration uses three patterns that you need to know before you change it.

Zoom bands. Martin clamps a minzoom or maxzoom to its layer's zooms. Where Planetiler changes a feature's settings by zoom, the configuration splits the layer into one layer per zoom band. Each band has its own min_size and buffer, and all bands write into one output layer with layer.

Conditions as zooms. A where that the PBF reader cannot check, such as one calling area() or a regular expression, makes Martin read every object in the file. The configuration puts such conditions into minzoom and maxzoom expressions instead. Martin leaves out a feature whose minzoom ends up above its maxzoom. In water_lakes_low, which draws large lakes up to z5, a lake below 25 km^2 gets a minzoom of 5 and a maxzoom of 0, so that layer leaves it out.

Selective merges. Planetiler merges only some features of a layer, such as only wood and forest in landcover. The configuration gives every other feature a hidden attribute _unmerged set to its feature id, osm_id * 10 plus 2 for a way or 3 for a relation. A way and a relation can share an osm_id, but no two features share a feature id, so they never merge.
